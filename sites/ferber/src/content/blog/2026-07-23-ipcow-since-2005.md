# IP Cow Since 2005

[ipcow.com](https://ipcow.com) has answered one question since 2005: *what's my IP address?*

That is a long time to keep a joke and a utility on the same hostname. The cow stayed. The stack did not. The live site is not a Jekyll page calling ipify. It is a first-party toolkit on hardware I pay for, in a country I picked on purpose.

## What it is now

The homepage still shows your public IPv4 and IPv6. Under that is the rest of the job: DNS, email posture, RDAP, connection tests, a URL shortener, a one-time secret, a short-lived file share. A hundred checks instead of one widget.

The constraint that matters: **your query does not go to a third-party lookup API.** DNS is DoH to [Quad9](https://quad9.net) by default (Cloudflare DNS only if Quad9 is briefly unreachable). Geolocation is self-hosted GeoLite2. RDAP comes from the RIRs. There is no Google font, no Google resolver, no Microsoft script, no Apple anything. Cookieless analytics, if any, stay on my infrastructure.

If DevTools shows a request to a Big Tech domain, I failed.

## Built for scripts

The original product, for anyone who lives in a terminal:

```bash
curl checkip.ipcow.com
curl -4 checkip.ipcow.com
curl -6 checkip.ipcow.com
curl 'checkip.ipcow.com?json'
```

Plain text. CORS open. Force a stack with `-4` / `-6`, or pin `checkipv4.ipcow.com` / `checkipv6.ipcow.com` from a browser. Every other tool has a JSON endpoint and a copy-paste `curl` recipe. If I cannot drop it into a cron job, it is not done.

The dual-stack story is not a badge. Ping, port check, HTTP check, traceroute, and the speed test run from IPv4 *and* IPv6 probes. A site that only answers on one stack will lie to you about the other.

## Why Germany

Every IP Cow server runs on Hetzner in Falkenstein. That is a legal choice as much as a hosting choice.

GDPR plus Germany's BDSG is a stronger floor than "we have a privacy policy." Traffic that never enters a US region is also traffic the CLOUD Act does not casually reach. Combined with no identifying analytics and no third-party scripts, the architecture and the jurisdiction are trying to say the same sentence: we are not in the business of having you.

Personal account data (saved secrets, notes, lookup history) is zero-knowledge — Argon2id + XChaCha20-Poly1305 in the browser. Operational data (domains you asked us to *monitor*) is encrypted at rest with a server key, because the monitor has to read it. I will not pretend "we can't read anything" for the work you hired the box to do.

## What sits in front

Caddy terminates TLS. An Astro SSR process on localhost serves the site. One proxy, several public names: the main site, a parked-domain placeholder, the admin, and the shortener hostnames ([73mp.net](https://73mp.net), [shortcow.com](https://shortcow.com), [n9a.us](https://n9a.us), [n48.us](https://n48.us)). Grey-cloud names hit the box directly. Orange-cloud names come through Cloudflare. Same origin, two failure pictures if the process dies — which is a story for the Caddy post, not this one.

SSH is not on port 22 from the internet. Heartbeats exist. That is the boring production shape, not a launch tweet.

## What I will not do

I will not put ads on an IP lookup. I will not route your DNS question through a "free API" that logs it. I will not tell you the old README is still true — the ipify / IPStack / Jekyll version is gone. If you cloned that repo, you cloned a museum.

Twenty years is not a brand story. It is a hostname that refused to die while the internet around it got worse at answering a simple question without taking a cut. The cow is still there. The lookups stay here.
