# Self-Hosting 101: The Lightweight Apps I Actually Run at Home

Most "self-hosting 101" lists read like a shopping cart: Kavita, Immich, Pi-hole, Uptime Kuma, Nextcloud, a password manager, a Git server, and three dashboards you'll never open again. I have run enough of those to know the useful version is smaller.

This is the set that survived. Each one is a Docker Compose directory on an Ubuntu box, or a Pi where that still makes sense. If it doesn't get used weekly, it doesn't stay.

## The rule

A homelab app has to beat the SaaS it replaces on at least two of three: **privacy, cost, control**. If it only wins on "I can say I self-host it," it is a toy. Toys are fine. They are not the 101.

Hardware can be a Raspberry Pi 4 or a small Proxmox VM. I run both. The apps below don't care.

## Pi-hole — ads and trackers for the whole LAN

I already wrote the [setup guide](/2026-03-25-pihole-setup-guide/). The 101 version is: one DNS sinkhole, DHCP pointed at it (or at Unbound in front of it), and every phone, TV, and laptop on the network stops asking Google's ad domains for permission to load a page.

It is the first thing I would stand up in a new house. It is also the thing guests notice without knowing why the internet "feels faster."

## Uptime Kuma — know when something died

I have a `~/uptime-kuma/` compose stack. It pings the rest of the lab and a handful of public sites. When Nginx Proxy Manager, a droplet, or the intranet goes quiet, I want a push, not a hunch.

Kuma is a Node app in a container, SQLite, a clean UI. It is not Prometheus. It does not need to be. Status page plus notifications is the whole job.

## Booklore — a library, not a streaming account

I don't run Kavita. I run [Booklore with OPDS](/2026-01-22-booklore-opds/), Wasabi behind it, and the same library on macOS and Android. If the 101 list still says Kavita, that's fine — it's a good reader. My stack settled on Booklore because it matched how I already store files.

The lesson is the same either way: pick *one* ebook server. Don't run two and "see which sticks."

## Donetick — chores that aren't in someone else's cloud

[Donetick](/2026-03-20-self-hosted-donetick-task-manager/) is a small Docker task manager with SQLite and an API. I still use Todoist for personal/work capture. Donetick is the homelab and household recurring stuff I don't want on a SaaS that can change its pricing page.

Two tools, two jobs. Collapsing them was how I used to lose both.

## Immich — photos that don't train someone else's model

Google Photos is the default because search is good and backup is easy. [Immich](/2026-05-19-degoogling-my-oneplus-12/) is the replacement that actually kept up: on-device capture stays local (Fossify Gallery), backup and ML search live on my server. I wrote the de-Googling post around that split on purpose.

If you only self-host one "big" app after Pi-hole, make it this or the ebook server. Not both in week one.

## Nginx Proxy Manager — one front door

[NPM](/2026-03-24-nginx-proxy-manager/) is how those containers get names and certificates without me hand-editing `server {}` blocks at 11 p.m. Let's Encrypt, a UI, done. Caddy does the same job on other boxes. Pick one reverse proxy and stop collecting them.

## What I would not start with

- **Nextcloud as the first app.** It will eat a weekend and a disk. Use it when you have a specific file-sync problem, not because a blog said "self-host your Drive."
- **Mail.** Deliverability is a job. I use Proton. The 101 is not Mailcow.
- **A Git server** until you have a reason `github.com` plus a local backup is insufficient.
- **Three dashboards.** One status tool (Kuma). The rest is procrastination with CSS.

## How I'd stand this up on a fresh Pi

1. Raspberry Pi OS or Ubuntu, static IP, SSH keys only.
2. Docker Engine + Compose plugin.
3. One directory per app, one `docker-compose.yml` each, the [update script](/2026-03-27-docker-compose-update-automation/) so you aren't `pull`/`up -d` by hand.
4. Pi-hole first, Kuma second, then *one* data app (photos or books).
5. Reverse proxy last, once something needs a name.

That's 101. Everything else is a sequel.
