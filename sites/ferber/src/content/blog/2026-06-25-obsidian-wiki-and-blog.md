# Publishing an Obsidian Vault as a Wiki and a Blog

Obsidian-Master is where I write. It is not a CMS. It is a folder of Markdown that happens to have two public lives:

- **Private wiki** — `intranet.example.com`, Caddy on `r2d2`, the runbooks and the domain table and the RustDesk gotcha.
- **Public blog** — `michalferber.me`, Astro inside tgwab-web, Cloudflare Pages.

One orchestrator: `publish.sh` (`intranet` | `blog` | `all`). Wrappers in `~/Obsidian` so I don't have to remember cwd.

## The wiki path

`VAULT_DIR` (the Intranet folder) rsyncs into the `intranet.example.com` repo's `content/`. Git commit, push, the box pulls and Caddy serves it. There is a guard: the script checks `origin` and the vault path against `.env.production` so I cannot publish Ferber into the intranet repo by fat-fingering a directory.

Indexes are generated (`update-intranet-indexes.sh`). Some tables — domain hardening — are generated by `dns-audit`. I don't hand-maintain 101 rows of SPF.

## The blog path

`Blog/posts/*.md` rsyncs into `sites/ferber/src/content/blog/`. Images, badges, certs go to `public/assets/`. A `sed` pass rewrites `../images/foo.webp` to `/assets/img/foo.webp` so Obsidian preview and Astro deploy both work. Then `pnpm --filter @tgwab/ferber build`. If Astro is mad, nothing pushes.

Drafts stay in `Blog/drafts/`. The glob is the publish list. That is the only draft system.

## Why not "just publish the whole vault"

Because the wiki has LAN IPs, recovery-domain notes, and client names. The blog has opinions and how-tos. Same brain, different blast radius. A single `publish.sh all` is convenient; it is still two rsyncs with two denylists in practice (the intranet guard, the blog's `posts/` only).

Relative image paths are the Obsidian concession. Absolute `/assets/` paths are the web concession. The rewrite is the glue. Don't make me remember which tree I'm in when I drop a screenshot.

## The habit

Write in Obsidian. Preview as a note. When it's true, `./publish-blog.sh` or `./publish-intranet.sh`. Cloudflare or Caddy does the rest. If I have to open VS Code to "make it a post," the pipeline failed.
